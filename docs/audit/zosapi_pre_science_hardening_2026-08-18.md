# ZOS-API pre-science hardening — 2026-08-18

This audit records the implementation changes made after the independent review of the first real OpticStudio 2026 R1 integration pass. It does not change the frozen optical/scientific targets and does not claim that A0/B0/C0, carrier/residual calibration, representative configurations, or Run72 have been executed.

## Scope

The hardening is intentionally limited to the ZOS-API acquisition/runtime boundary and frozen analysis provenance.

### Binary 4

- `Par4` (`Sine(delta0)`) is treated as an OpticStudio-computed diagnostic column.
- Project code verifies the `Par4` header but never writes the cell.
- Binary 4 aspheric/phase term counts are fail-closed at 20 terms per zone.
- A unit regression asserts that `configure_binary4()` leaves `Par4.DoubleValue` untouched.

### Huygens PSF

- Returned grid dimensions must equal the requested image sampling, not merely agree with `Nx/Ny` metadata.
- `MinX/MinY/Dx/Dy` must be finite; `Dx/Dy` must be positive and equal the requested `ImageDelta`.
- The returned array midpoint must remain centered on the Zemax geometric reference within half a sample. No PSF-peak recentering is introduced.
- Intensity samples must be finite and cannot contain materially negative values.
- The parser still copies the complete grid into pure Python data before the analysis is closed.

### Frozen acquisition provenance

`AnalysisSettings` now includes the ZOS acquisition controls that can change scientific output:

- Huygens `Normalize`, `UseCentroid`, `UsePolarization`;
- Zernike sample size and maximum term count;
- Zernike OPD-reference flag, center, normalized radius, obscuration epsilon, and image-surface selection.

`HuygensPsfSettings.from_analysis_settings()` and `ZernikeStandardSettings.from_analysis_settings()` provide the production path from the frozen settings object to the ZOS-API settings object. The settings hash therefore changes if these acquisition controls change.

All relevant floating-point settings now reject NaN/Inf before a frozen settings hash can be used.

### Python.NET / ZOS process bootstrap

- CLR/ZOS assembly loading is now process-idempotent.
- Repeated sessions from the same OpticStudio installation reuse the already loaded ZOS API module.
- A single Python process refuses to switch to a different OpticStudio installation path after CLR/ZOS initialization; a new Python process is required.
- A unit test verifies the identity rule.
- A real Zemax stress test opens, creates a new sequential system, and closes ten sessions in one process to exercise the native lifecycle that previously produced occasional warnings.

## Validation status

The parent integration branch had reported 83 unit and 5 Zemax tests. Those counts remain historical evidence for the parent branch only.

The hardening branch was rerun on 2026-08-18 with OpticStudio 2026 R1.00 and a Premium ZOS-API license:

- `pytest tests/unit` → 94 passed
- `pytest tests/zemax` → 6 passed in 175.14 seconds
- `ruff check .` → PASS
- `compileall` → PASS
- `uv lock --check` → PASS

The six-test Zemax suite passed the frozen 128×128 pupil / 256×256 image Huygens acquisition, Binary 4 / Even Asphere / Coordinate Break round trip, the ten-session process stress test, the worker session, and the frozen 32×32 / 37-term Zernike acquisition. The captured run did not reproduce the earlier `FRU__delta_init()` warning or a native process exit.

The worker session was also run by itself in a new Python process:

```powershell
uv run pytest tests/zemax/test_zos_worker_gate.py -k worker_thread_session_risk_gate -vv
```

Result: 1 passed, 2 deselected in 9.94 seconds. The shorter expression `-k worker` also matches the test filename and selects all tests in that file, so it is not used as the worker-first command.

Ruff initially found two import-order errors in new unit tests. They were corrected before the final 94-test and Ruff rerun.

## Scientific STOP conditions unchanged

- TDD-999 remains closed until versioned WFS/RAD/HOA residual payloads and numerical piston/global-defocus calibration policy are available and validated at low/median/high actual carrier powers.
- Formal A0/B0/C0 and carrier locks have not been generated by this hardening.
- Three representative configurations still require sampling convergence and independent Huygens-MTF cross-check before Run72.
- No `.zos` or `.zmx` scientific asset is added by this change.
